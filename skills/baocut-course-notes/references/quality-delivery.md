# 内容复核与可阅读交付

适用于质量复核、多课批量、手机阅读和PDF/ZIP导出。先确认用户要的是摘要还是完整笔记；不把所有场景都扩大成研究论文审计。

## 复核证据，而非润色措辞

复核时直接读原始转写与官方讲义，不只读初稿。优先核查：

- 定义、公式、代码示例、关键数字、因果链是否成立；可执行的小算例/JSON直接运行验证。
- 指标的分母、模型、样本筛选、预算、数据划分、消融与主结果是否混淆。把特定实验限制写回来，不扩大成普遍规律。
- 讲师“我猜/据说/我的经验”是否被改成事实。讲义中未讲的部分要标补充，不编造课堂时间码。
- 学生提问不清楚时，以讲师复述为依据，并保留不确定。术语校正保留原文副本，不用顺口词替换猜测。
- 公式/代码/案例和现场问答是否在压缩中消失；核心段落能否沿时间码回查。阅读分块不等于语义章节。
- 视频帧是否处于完整动画状态、caption是否超出可见证据；PDF物理页码与印刷页码分开，讲解时间和真实截帧时间分开。

每项实质发现记录：问题、修改前后、原句ID/时间或讲义页、修复验证、仍未知什么。制作期间发现并避免的风险，与交接初稿中真正修复的问题分开计。读了讲义不等于读了它引用的全部论文。

## 逐图完整性验收

本节只核对已入选图片；完整视频笔记还必须做 [视频视觉覆盖](visual-coverage.md)，盘点未入选画面。图片数多、全句 source_ids 和逐图 passed 都不能证明视频没有漏掉新信息。

以每张入选图的教学用途确定应有信息，再对照实际像素与来源。静态 PPT 默认选核对版本后的完整官方页；视频帧用于板书、动态演示和讲义没有的状态。导航帧只用于定位，不能直接作为成品。检查同一页的后续展开；标题一致、同秒重抽高清、图片计数和解码成功都不代表内容完整。

- 列表逐项核对；公式查等号两侧、上下标和边界；图表查坐标、图例、箭头和结论。PDF 也可能有裁断、缺公式或仅保留动画初始状态。
- 动画的完整性按论证链判断。最终状态若覆盖中间步骤，保留必要阶段；PDF 只有演示初始界面时，保留视频中的结果或操作步骤，不机械全换讲义。
- 已知缺项须补帧、换页或补阶段图。源页自身缺陷无法换图时，回查转写、相邻页或视频后在图旁加“整理者补注”，写出缺失内容和证据；无法核实就保留 known_gap，不得验收完成。仅修改图注为“尚未展开”不算修复。
- 按内容核对物理 PDF 页码，不拿视频页内编号直接当 PDF 页码。讲解时间是导航，不能把 PDF 标成同秒视频截图。

对所有最终入选图保存 `image-audit.json`，图片修改后重新查看并更新记录。最低格式如下（section/frame 均一基，path 相对 notes.json）：

```json
{
  "schema_version": 1,
  "notes_sha256": "当前notes.json的SHA256",
  "images": [{
    "section": 1, "frame": 1, "path": "frames/page-003.png", "sha256": "当前图片的SHA256",
    "purpose": "解释三个阶段的条件关系", "expected_information": "三阶段、箭头和成立条件",
    "observed_information": "已目视确认三阶段文字、两条箭头与条件完整可见",
    "comparison_evidence": "与官方PDF物理第3页及相邻展开状态对照",
    "sources": [{"path": "../sources/slides.pdf", "sha256": "来源文件的SHA256", "detail": "物理第3页"}],
    "status": "passed", "known_gap": false, "resolution": "换用完整页；重新目视对照"
  }]
}
```

运行 `python3 <skill>/scripts/validate_image_audit.py --notes <run>/notes.json --audit <run>/image-audit.json`。该工具只检查逐图记录覆盖、文件版本和声明状态，不识别像素语义，也不能证明代理真的查看过图片。不得为了过门槛填写未经执行的检查。缺记录、pending、known_gap 或哈希过期会阻止图片验收完成；HTML、PDF 与真实设备仍分别验收。

修改配图后，重建本次已交付的所有受影响 HTML、单课 PDF、合集和 ZIP；保留自定义正文、补充、样式与交互。记录源 notes/HTML 及导出哈希，回读包内文件对应当前版本，不能把新版 HTML 和旧版 PDF 混交。未要求、也未曾交付的格式不因本规则额外生成。

## 单课阅读优先

多课或手机阅读场景建议按视频单独交付；用户明确指定形式时遵从其要求。建议每课提供短摘要、按语义分节的详细笔记、贴近论证的图、自测及可回查来源；不固定节数、字数、图片数。多个课可以另加总索引与跨课关联，合集不能成为唯一入口。

先验证一课最容易出错的阅读样板：长标题、窄屏目录、公式、代码、细小图表、图片放大。放大不能只是把同一缩略图装进弹窗；窄屏须能查看原尺寸细节，并在受限滚动容器内平移，关闭/适合屏幕控件保持可用。桌面窄屏模拟与真实手机打开要区分。拆小文件只减少加载和导航负担，不自动证明排版已改善。

## HTML、PDF与压缩包分别验收

- HTML：正文与所有内容图可离线读取；本地资源和锚点有效；无重复ID；移动布局不横向溢出；实际操作目录/放大/关闭，并看打印与控制台。连接拒绝、预览未启动、标签失效与安全策略拒绝分别诊断：前者先核对并恢复任务范围内的本机预览，或用获准的 browser use / computer use 验收；不能因一种接口失败就跳过 UI。明确的安全策略拒绝不绕过，仍不可用时才如实标待验，并记录已尝试的合规路径。
- PDF：需要时使用当前可用的PDF技能与运行环境，不复制某台Mac的固定字体路径。字符要有字体覆盖，缺字应显式失败或经过有记录的等价排版，不静默丢失。图+图注成组；时间码与标题保持同页；表格、列表、公式、摘要和补充均计入正文保真检查。
- PDF验证：检查每个正文文本块和图像是否进入成品、合辑页与单课页一致、目录与书签正确；另选代表页实际目视。全量程序化检查不能称为全页目视检查。提取器不能仅拿自己支持的标签作为“全部正文”标准，应独立盘点HTML中的列表、表格等内容类型。
- ZIP：优先相对链接，复制需要的资料且避免重名；内部链接与锚点、图片解码、ZIP完整性均要检查。原视频/论文等外链可需联网，但要告知；不为“离线”而无边界复制全部媒体。

每次修正文稿都重建受影响的导出，并记录源HTML/notes哈希。只交当前版本，别让新HTML与旧PDF进入同一包。无需为了测试重跑已稳定且未改动的所有媒体阶段。

## 状态与证据边界

`review.json`分别记录内容、结构、桌面、窄屏、真实手机、PDF、打包的状态（passed / pending / blocked / not_requested），附验证方法、时间和证据路径。`outcome=completed`仅在本次要求的门槛通过时使用；其余用partial/failed并说明。

最终回复直接给每课文件地址、实际阅读范围和关键剩余问题。用户仅要文件时不重复长篇工程日志。未测试的格式不能用“已验证另一格式”代替。


## 阅读布局复核

详细 HTML 按 [阅读布局与图文整合](editorial-layout.md) 检查 `reading-layout.json` 的版本绑定和内容完整性，再语义复核关键判断、关键词及补充与图的放置。来源区分通过标签和回查信息保留，不以课堂/课后两个大区块替代知识点整合。实际操作自测展开、收起、回查，确认问题与答案有足够视觉区分；检查窄屏目录和图片原尺寸查看。打印的折叠内容保留、打印媒体模拟与原生打印预览分别记录。结构通过不等于语义或 UI 通过，样板课通过不等于整批通过。
