# 阅读布局与图文整合

详细 HTML 默认使用 `reading-layout.json` 和随 Skill 提供的 editorial 模板。`notes.json` 保存事实、来源和时间归属；布局文件保存阅读顺序、导航、重点与资料的展示位置。这层分离便于在保留信息量和证据的同时改善阅读，不要求重转写或改写已审内容。用户明确指定其他输出形式或风格时遵从本次要求。

## 先按论证组织，再标明来源

完整阅读现有正文、例子、整理者说明、补充及图注，再决定每组材料回答了哪个课堂问题。补充放在该问题或结论旁边，相关图紧跟补充说明；课堂配图也应贴近解释它的段落。不要把所有课堂文字、所有图片、所有课外资料分别堆成三个区块。确实独立的延伸主题可以保留为明确的延伸阅读，但需说明与主线的关系。

来源仍须清楚区分：课堂口述、讲义未展开部分、论文补充与整理者解释不能因为一起排版就混成讲师原话。沿用 source_label、原始链接、物理页、真实视频帧时间和阅读边界；不要给补充材料发明课堂时间。原文中“见文末补充”等导航语句若失真，应最小改正后重新绑定布局哈希，并记录修改；不要趁排版删掉重复但有意义的信息。

每节的 `takeaway` 是一句忠实的关键判断，界面标为整理者提炼；它帮助抓重点，不代替详细正文。关键词从该节实际展示的原句中挑选少量准确短语，优先概念、条件和关键差异，不加粗整段或每个术语。模板每个文本块最多强调两个匹配片段；判断哪些词值得突出仍由整理者负责。

## 布局数据合同

顶层结构示意如下；真实文件必须覆盖该笔记的全部内容单位：

```json
{
  "version": 1,
  "notes_sha256": "notes.json 原始字节的 SHA-256",
  "course_title": "课程名",
  "issue": "课次标识",
  "title": "简短主标题",
  "subtitle": "说明这一课解决什么问题",
  "summary_title": "先把握本课主线",
  "summary_terms": ["摘要中确实出现的关键短语"],
  "groups": [{"start": 1, "label": "一 / 理解问题"}],
  "sections": [{
    "short": "目录短标题",
    "takeaway": "本节关键判断。",
    "terms": ["正文中的准确短语"],
    "flow": "p0 f0 x0 f1"
  }],
  "bridges": {"x0": "说明这份补充怎样回答刚才的问题。"}
}
```

`version`、`notes_sha256`、`sections` 必填。`sections` 与原始章节数量及次序一一对应，每项须有非空 `short`、`takeaway` 和字符串 `flow`。标题、摘要标题、分组、术语和衔接可按内容设置；`groups[].start` 是一基章节号，保持阅读顺序、不重复。展示文字均为纯文本，不在字段中塞 HTML。

`flow` 用空格分隔 token：

| Token | 指向 |
| --- | --- |
| `pN` | 本节 `paragraphs[N]` |
| `eN` | 本节 `examples[N]` |
| `nN` | 本节 `editor_notes[N]` |
| `fN` | 本节 `frames[N]` |
| `fS:N` | 原第 S 节 `frames[N]`；S 为一基章节号 |
| `xN` | 全局 `supplements[N]`，兼容旧字段 `official_slide_supplements` |

所有 N 为零基索引。每个原始段落、例子、说明、图片和补充必须在整个布局中恰好出现一次，不能遗漏或重复。跨节引用仅允许 `source_type=pdf_page` 的资料图；视频帧必须留在其真实时间所属章节。跨节只是改变展示位置，不修改原始来源及时间证据。

模板把 `xN` 后连续的 `f…` 作为同一个补充图文单元；接到其他类型 token 时结束该单元。因此先写补充说明，再接真正解释它的图，不让图片夹到无关正文里。不要为了凑邻接强塞无关图。没有适合图片的补充可以只用文字。

`terms` 必须在本节实际展示的 p/e/n/x 文本中精确出现；图注或标题中才有的词不能代替正文匹配。`summary_terms` 从原摘要选择。`bridges` 的键只能是已有 `xN`，文字以“整理者衔接”展示；它可连接现有论证，不能加入未经来源支持的新事实。

## 生成、校验与失效

冻结事实内容后计算 notes 原始字节哈希，写入布局。渲染命令：

```sh
python3 <skill>/scripts/course_notes.py render \
  --notes <run>/notes.json --index <run>/chunks/index.json \
  --layout <run>/reading-layout.json --require-layout \
  --out <run>/课堂笔记.html
```

同目录的 `reading-layout.json` 可自动发现；交付时保留 `--require-layout`，使布局缺失时明确失败，不静默退回旧版长文样式。旧版渲染路径保留用于兼容或用户明确要求，不能据此把未完成的阅读布局标为完成。

`reading_layout.py` 校验版本、SHA、章节数、引用范围、全部内容恰好一次、跨节视频帧禁用以及正文术语匹配。它不判断补充放置是否合理、提炼是否忠实、配图是否可读，也不能证明阅读完成。渲染通过后还要逐节检查这些语义问题。

notes 发生任何修改后，旧 SHA 会使布局失效。先复核修改影响到的顺序、术语、提炼和配图，再刷新哈希并重渲染；不能只机械更新哈希来绕过复核。将布局、模板版本、notes、图片与最终 HTML 纳入产物依赖，布局或模板变化也会使已有 HTML 的相关验收失效。

## 模板与验收边界

模板统一主标题、正文行宽、留白、目录和图注层级；桌面侧边目录与窄屏折叠目录各需实际检查。自测以显著的问题区和独立答案区呈现，答案默认折叠，支持展开、收起与回查章节。图支持放大及原尺寸查看，来源保留在可展开区域。样式可以适应课程，但不要为追求简洁削掉正文、来源或适用边界。

按 [复核与交付](quality-delivery.md) 验收：

- 静态核对内容保留、锚点、重复 ID、图片存在、最终 SHA；语义复核补充→主题→图的对应及关键词选择。
- 实际浏览桌面和窄屏，检查行宽、横向溢出、长标题、图文邻接、来源可读；操作目录、自测展开/收起/回查和图片放大/关闭/原尺寸，查看控制台。仅截图不能证明交互完成。
- 打印时应包含折叠答案、来源和阅读范围，并检查分页与图注。模板的 beforeprint/afterprint 处理和 print CSS 只是机制；静态事件测试、浏览器打印媒体模拟与原生打印预览分别记录，不能互相冒充。
- 逐课记录已验范围。某一课或某一屏宽通过，不代表整批或真实手机已验收。只做结构检查时保持视觉待验；保留来源阅读和视频覆盖的既有缺口。
